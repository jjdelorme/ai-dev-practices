02 // Strategic Positioning

Why Levels 3 & 4 Are the Enterprise Sweet Spot

Overcoming the Level 2 review bottleneck while managing the supervision, drift, and liability risks of Level 5.
!Why Level 2 Plateaus
  • The Proofreader Bottleneck: AI generates code 10x faster, turning senior engineers into exhausted syntax reviewers.
  • The "Dumb Zone" in Long Chats: Crossing ~40% context (~150k–200k tokens on a 1M window, Dex Horthy) degrades reasoning; auto-compaction loses constraints.
  • Reward Hacking: Unsupervised single-agent loops delete or weaken failing tests to report "Green."
⚠Why L5 Is an R&D Frontier (ASDLC.io)
  • Paradox of Supervision & Silent Drift: ASDLC.io warns that L4/L5 isolation causes human context atrophy while passing tests mask divergence from intent; StrongDM requires full Digital Twins (DTUs) to compensate.
  • Unpriced Liability: Stanford Law (Eran Kahana, "Built by agents, tested by agents, trusted by whom?") highlights accountability gaps when no human can attest Signed-off-by provenance.
  • Spec Maintenance Overhead: As Birgitta Böckeler (MartinFowler.com) notes, making specs exhaustive enough to replace code shifts teams from debugging code to debugging prose.
✓The 4-Gate L3/L4 Architecture
  • 👤 Human Gate 0 (Approve Spec): Socratic 15-min pre-design loop + Spec/Delta (30s leaf bugfix / 3m seam feature sign-off).
  • 🤖 Auto Gate 1 (Blind Spec Check): Fresh zero-context Goldfish checks the written spec for blind spots before any code is written.
  • 🤖 Auto Gate 2 (Sandboxed Build & Test): Isolated worktree builder runs verify() + Adversarial Critic + 100ms Jev diff audit.
  • 👤 Human Gate 3 (Approve Merge): Change Owner audits Critic/Jev verification receipt & parity results before merge.

"Humans govern only the bookends (Gate 0 & Gate 3) because Machine Gates 1 & 2 enforce isolation, TDD, and anti-reward-hacking automatically."

* Sources: ASDLC.io Levels of Autonomy (Paradox of Supervision, Silent Drift & Eran Kahana / Stanford Law) | StrongDM Software Factory | Birgitta Böckeler, MartinFowler.com | Dex Horthy, The Dumb Zone.
03 // Cutting Through Framework Opinion

Ceremony to Strip vs. The 5 Non-Negotiables

Most public frameworks mix 30% essential mechanics with 70% Agile theatre. Keep only what carries load at L3/L4.
✕Strip Out: Process Opinion & Ceremony
  • 1. Multi-Persona Agile Roleplay (BMAD 21 Personas): Passing prose from AI Scrum Master → AI PO → AI UX → AI Dev causes telephone-game drift. Even AWS AI-DLC v2.0 killed specialist chains for "Small Mob, Broad Agents."
  • 2. 30+ Intermediate Human Approval Gates: Clicking "Approve" on 15 markdown artifacts induces Gate Fatigue (rubber-stamping). Collapse human gates to Gate 0 (Spec) and Gate 3 (Merge).
  • 3. Bloated Auto-Generated AGENTS.md Files: ETH Zurich (Gloaguen et al., Feb 2026) proved /init context files reduce task success and raise token cost >20%. Put code style in ruff/eslint and enforce AGENTS.md < 80 lines via a 3-line Python check in verify.sh.
  • 4. Monolithic Specs for Small Brownfield Edits: Writing a 4-file greenfield constitution for a 3-file bugfix guarantees engineers bypass it. Use OpenSpec Delta Specs (ADDED / MODIFIED / REMOVED).
★Keep: The 5 Load-Bearing L3/L4 Primitives
  • 1. Elephant vs. Goldfish Context Isolation (Dave Rensin): High-context Elephants plan specs; zero-context Goldfish check specs for blind spots and execute atomic tasks in fresh windows.
  • 2. Single Abstracted verify() Tool + Hard Stop Gate: Expose one verify() script (build + lint + test) returning concise errors, enforced by a deterministic Stop gate that blocks early exit.
  • 3. Independent Critic & External Holdout Tests (.holdouts/): A fresh Critic checks spec.md + git diff, while Holdouts (StrongDM Attractor) store end-to-end acceptance tests in a separate directory outside the agent's Git worktree (e.g., ../project-holdouts/) executed by CI/the outer harness after coding finishes—so the agent can never read or edit the test assertions.
  • 4. Right-Sized Codebase Context (Scaled by Repo Complexity): Start with minimal AGENTS.md (<80 lines) + subfolder AGENTS.md; add OKF for cross-cutting domain/data rules, and GraphDB call graphs only for large monoliths.
  • 5. Ephemeral Worktree & Clean-Room Sandboxes: Run parallel builders in isolated Git worktrees/containers where legacy source and holdout tests are never mounted into the builder's workspace.
* Sources: Gloaguen et al., ETH Zurich (Feb 2026, arXiv:2602.11988 — Evaluating AGENTS.md) | ASDLC.io AGENTS.md Spec | BMAD-METHOD | AWS AI-DLC v2.0 | OpenSpec | StrongDM Attractor.

05 // Scaling Codebase Context by Repo Complexity

Scaling Codebase Context: AGENTS.md → OKF → GraphDB

Match how agents discover repository and domain context to the size and coupling of your codebase.
1Tier 1: Root & Folder AGENTS.md

SMALL / MODULAR REPOS: Greenfield & Bounded Services

  • Root AGENTS.md (<80 Lines): Holds only universal build/test commands (./scripts/verify.sh) and hard repo boundaries.
  • Scoped Subfolder AGENTS.md: Both agy and Claude Code auto-load subfolder AGENTS.md / CLAUDE.md files only when the agent touches files in that directory.
  • Where It Hits a Wall: Folder docs map 1:1 to code directories—they cannot express cross-cutting domain rules spanning multiple services, staleness SLAs, or when legacy folders are deleted in a rewrite.
2Tier 2: Open Knowledge Format (OKF v0.2)

MEDIUM / DOMAIN-HEAVY REPOS: Cross-Cutting Rules & Schemas

  • Progressive Discovery via index.md & Links: Agents read a lightweight root index.md, scan YAML frontmatter (title, description, tags), and follow standard Markdown links ([customers](/tables/customers.md)) on demand.
  • First-Class Provenance & Freshness: Every concept tracks sources, trust tier (verified: {by: human:id}), and expiration (stale_after).
  • Decoupled from Code Folders: Captures portable business logic, SQL schemas, and playbooks that survive even when legacy code is thrown away.
3Tier 3: GraphDB (Structural & Semantic Graph)

LARGE / TANGLED MONOLITHS: Deep Call-Chains & Extraction

  • Auto-Extracted Call & Feature Map: Parses AST call graphs + DB schemas and clusters functions by semantic verb-object descriptors into a Neo4j graph.
  • Instant Blast-Radius & Risk Scoring: Queries upstream callers (impact) and composite risk (fan-in, I/O volatility, git churn) in milliseconds without reading 50 files.
  • Automated Seam Discovery: Pinpoints Michael Feathers' Object Seams and clean-room refactoring slices to feed into OKF specs.

Progressive Scaling Rule: Use Root + Subfolder AGENTS.md for folder-local code rules → Add OKF (with index.md link traversal) for cross-cutting domain/data schemas → Add GraphDB when monolith call-chains outgrow grep/LSP.

* Sources: ETH Zurich AGENTS.md Study | GoogleCloudPlatform OKF v0.2 Spec (§3 index.md Progressive Disclosure & §6 Cross-Linking) | jjdelorme/graphdb-skill.
06 // Production Frontier Case Studies

Learned Practice at Scale: Google, Spotify, AWS & StrongDM

Convergent architectural patterns from four industry pioneers of agentic software engineering.
GGoogle ("Elephants & Goldfish" & OKF)
  • Elephant vs. Goldfish Split (Dave Rensin): Spend 15+ minutes in a Socratic Elephant session debating edge cases; hand the written spec to a zero-context Goldfish to expose blind spots before coding.
  • "Undo When Adrift" & Shift Verification Left: Never argue with a drifting agent in chat—git reset --hard, fix the spec, and run fast local builds/unit tests instead of slow end-stage UI tests.
  • Open Knowledge Format (OKF v0.2): Git-native Markdown + YAML provenance (verified, stale_after) with progressive index.md link discovery.
SSpotify ("Honk" & Fleetshift)
  • Solving the 70/30 Wall: AST codemods (OpenRewrite) handle 70% of mechanical upgrades; Honk (Claude Code in K8s pods) solves the 30% semantic tail (1,500+ PRs; 60–90% time saved).
  • 4 Prompt Engineering Rules: (1) Declarative end-state over steps, (2) Explicit "When NOT to Act" preconditions, (3) Few-shot git diff examples, (4) One atomic change per run.
  • Single verify() MCP Tool: Hides raw Maven/Gradle/Docker logs behind one tool returning concise errors + Independent Judge blocking out-of-scope diffs.
AAWS (AI-DLC v2.0 Workflows)
  • "Small Mob, Broad Agents": v2.0 replaced fragmented specialist handoffs with 11 broad agents + deterministic Bun/TS state engine (93 tools, 19 hooks) to stop context loss.
  • Cryptographic codekb Scope Diffing: Brownfield reverse-engineering hashes touched modules to auto-select Reuse KB (0s), Focused Scan, or Full Rescan.
  • Adaptive Depth Over Ceremony: Skip the 33-stage default profile; use bugfix (9 stages) or express (10 stages) + 6 Brownfield Safeguards.
DStrongDM (Attractor) & Superpowers
  • External Holdout Scenarios (.holdouts/): Originated by StrongDM Attractor—acceptance tests live in a separate directory outside the builder's Git worktree so agents cannot read or game them.
  • Superpowers Iron Law TDD: Enforces strict Red → Green → Refactor where no production code is permitted until a reproduction/spec test fails first.
  • Walking Skeleton First (U1): Build and verify Unit 1 (scaffold, DB migration, auth, CI, verify() gate) before fanning out parallel wave swarms.
* Sources: Dave Rensin (Google), Elephants & Goldfish & GCP OKF v0.2 | Spotify Honk: Pt 1–Pt 4 | AWS AI-DLC v2.0 | StrongDM Attractor.

☾Why "Dreaming" Happens Outside the Inner Loop
  • Don't Mutate Rules Mid-Flight: During L3/L4 execution, Goldfish builders need frozen, deterministic instructions. Updating memory mid-task causes rule drift.
  • When to Invoke in L3 (Interactive): Run /learn after you nudge an agent, fix a subtle environment quirk, or merge a complex PR so no team member repeats that debugging session.
  • When to Invoke in L4 (Factory "Dreaming"): After a nightly wave swarm or fleet run finishes, an automated post-mortem pass inspects aborted/failed builder runs and runs /learn to propose systemic fixes.
✓What /learn Actually Writes (And How to Prevent Bloat)
  • 1. Root & Folder AGENTS.md Updates: Proposes high-signal environment/build commands or directory-specific architectural boundaries discovered during the session.
  • 2. New Reusable SKILL.md Packages: Proposes dedicated skills (.agents/skills/<name>/SKILL.md + helper scripts) loaded on-demand only when relevant—keeping base context near zero.
  • 3. The Graduation Rule: If a proposed AGENTS.md bullet can be checked mechanically (e.g., banned imports, SQL patterns, or line limits), convert it into a linter rule or verify.sh check so AGENTS.md never exceeds 80 lines.

!Who Actually Manages the Task DAG (plan.md vs. tasks.json)?
  • In L3 CLI (Non-Deterministic): In interactive CLIs (agy /plan, SpecKit, OpenSpec), the LLM updates Markdown checkboxes (- [x]) in plan.md via prompt instructions. Convenient, but an agent can prematurely tick its own box.
  • In L4 Harness (100% Deterministic): The LLM writes tasks.json once at Gate 0. During execution, Python parses the DAG (graphlib.TopologicalSorter) and only Python marks a task "COMPLETED" in tasks.json after verify.sh exits 0.
★How External Holdouts (.holdouts/) Actually Work
  • Separate Directory Outside the Worktree: Acceptance tests live in a sibling directory or separate repo (e.g., ../project-holdouts/) that is never mounted into the coding agent's Git worktree.
  • Outer CI Execution at Gate 3: After the builder finishes and passes unit tests in verify.sh, the outer harness or CI runs pytest ../project-holdouts against the built app so agents can never inspect or game the acceptance assertions.

12 // Reference Harness Code & Human-in-the-Loop UX

Reference L4 Harness: Host Loop Owns DAG & Retries

Why deterministic retry caps and DAG state live in the outer runner (factory_harness.py)—not inside verify.sh.
factory_harness.py — Python owns tasks.json DAG & retry counter
import subprocess, jev  # TypeSafe System One (100ms calibrated gate)
from google.antigravity import Agent, LocalAgentConfig, CapabilitiesConfig

async def run_goldfish_unit(spec_path: str, worktree_dir: str) -> str:
    spec = open(spec_path).read()
    # Gate 1: Zero-Context Goldfish Blind-Spot Spec Check
    check = await Agent(
        model="gemini-4-argon",
        config=LocalAgentConfig(workspace=worktree_dir,
            capabilities=CapabilitiesConfig(can_write_files=False, can_run_commands=False))
    ).query(f"Reply AMBIGUOUS: <gaps> or CLEAR:\n{spec}")
    if "AMBIGUOUS:" in check.text:
        raise RuntimeError(f"Gate 1 Blind-Spot Check Failed:\n{check.text}")

    # Gate 2A: PYTHON holds `attempt` in memory & runs verify.sh OUTSIDE the LLM
    feedback = ""
    for attempt in range(1, 3):  # Deterministic outer loop cap (ASDLC max_execution_loops)
        await Agent(model="gemini-4-argon",
            config=LocalAgentConfig(workspace=worktree_dir)).query(
            f"Implement via TDD in this worktree:\n{spec}\n{feedback}")
        res = subprocess.run(["./scripts/verify.sh"], cwd=worktree_dir, capture_output=True, text=True)
        if res.returncode == 0:
            break  # Python now marks task COMPLETED in tasks.json
        feedback = f"Attempt {attempt} verify.sh failed:\n{res.stderr[-1000:]}"
        if attempt == 2:
            subprocess.run(["git", "reset", "--hard", "HEAD"], cwd=worktree_dir)
            raise RuntimeError("Max Attempts Failed: Reverted worktree; fix spec")

    # Gate 2B: 100ms System One (Jev) Audit before opening Human Gate 3 PR
    diff = subprocess.run(["git", "diff", "HEAD~1"], cwd=worktree_dir, capture_output=True, text=True).stdout
    v = await jev.AsyncClient().evaluate(state={"spec": spec, "diff": diff}, questions={
        "tampered": jev.boolean("Did the diff delete or weaken any test?"),
        "parity": jev.score("Spec parity", levels={0: "Low", 100: "Full"})})
    if v["tampered"].prob > 0.15 or v["parity"].value < 85:
        raise RuntimeError(f"Blocked by Gate 2B: {v}")
    return "OPEN_PR_WITH_VERIFICATION_RECEIPT"
⚙Why State Lives in the Outer Runner
  • verify.sh Is Stateless: A shell script only returns exit code 0 or 1. To cap retries deterministically (like ASDLC.io's max_execution_loops), the outer Python/JS runner holds the loop counter in memory and calls verify.sh outside the LLM.
  • Who Mutates tasks.json? Python's TopologicalSorter reads tasks.json, dispatches waves, and updates "status": "COMPLETED" on disk only after res.returncode == 0.
  • Human UX (Gate 0 & Gate 3): Architects lock the spec in agy at Gate 0, run factory_harness.py in the background, and review the PR + Verification Receipt at Gate 3.
* Sources: ASDLC.io L3 Harness Config (max_execution_loops) | Antigravity Python SDK | TypeSafe Jev SDK Docs.
