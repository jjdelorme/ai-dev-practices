THE PHILOSOPHY

The Mindset Shift

AI is a Teammate, Not Just a Tool
  • Shift Perspective: Move from "Prove it to me" to "Iterative Partnership". Co-create and collaborate rather than treating the AI as an external adversary.
  • Fingerspitzengefühl (Fingertip Feeling): Success requires hands-on intuition. You cannot learn this from a book; practice to develop the "tact".
  • Ownership: Humans must own the results. AI assists, but you define the standard, verify outcomes, and steer direction.
THE SPECIFICATION

Prompting is Specification

Writing Effective Instructions for LLMs
  • Use Examples (Few-Shot): The #1 tip; often more effective than zero-shot. Provide concrete input-output pairs to anchor the model's behavior.
  • Clear, Explicit Instructions: Be precise; treat the LLM like an intern. Avoid ambiguity; define exact schemas, constraints, and success criteria.
  • Iterate and Experiment: Test, refine, and avoid superstitious additions. Don't add phrases based on folklore; measure prompt improvements systematically.
  • Leverage Models: Use LLMs to generate or improve prompts. Ask a stronger model to draft system instructions or build few-shot examples.
  • Provide Context Effectively: Place important data at top; use delimiters. Structure inputs with clear boundaries (e.g. XML tags or Markdown) to aid parser efficiency.
THE WINDOW

Context Engineering

Managing the Finite Resource of Context
  • Context Poisoning: Hallucinations and inline errors are repeatedly referenced. A single incorrect output in history can loop back, reinforcing future errors.
  • Context Distraction: Model over-focuses on long context, neglecting system core instructions. Too much raw text dilutes attention, leading the model to ignore foundational prompts.
  • Context Confusion: Superfluous, redundant info leads to low-quality responses. Keep context highly relevant; prune old, dead, or irrelevant discussions.
  • Context Clash: New info or tool output conflicts with core design assumptions. Discrepancies between historical context and current guidelines baffle the LLM.
  • The Fix: Hawkish Context Management. Use focused sessions for specific tasks, avoid sprawling chats, and minimize tool/MCP registrations.
THE METHODOLOGY

Spec-Driven & Test-Driven Development

Architecture Before Code
  • Plan First: Iterate on a spec with AI before coding. Establish schemas, API signatures, and behavioral limits prior to any implementation.
  • Small Batches: Keep tasks small, focused, and specific. Smaller context windows lead to highly precise code edits and zero structural degradation.
  • TDD: AI writes tests first to define success (Red-Green-Refactor). Lock down specifications via unit/integration test assertions before writing logic.
  • BDD: Use Gherkin style specs for behavior validation. Write human-readable feature descriptions so both human and agent share identical goals.
  • Rubber Ducking: Talk through complex problems with AI to clarify thoughts. Treat the agent as a sparring partner to stress-test your design and assumptions.
THE REAL WORLD

Working with Legacy Code

Applying Modern Agents to Existing Systems
  • Identify Seams: Find safe places to decouple dependencies. Identify interfaces or boundaries where you can alter behavior without editing old, fragile blocks.
  • Characterization Tests: Agents write tests to lock in legacy behavior. Document and preserve the current output of the system before any refactoring starts.
  • Strangler Fig Pattern: Gradually replace system edges. Iteratively migrate functions to clean structures, routing calls away from the old core.
  • Safety Net: Heightened importance of tests before refactoring. Never allow an agent to rewrite code without a robust, verifying test suite in place.
  • Enable Change: Break dependencies ➔ Test ➔ Refactor (The Feathers Method). Follow strict legacy-code practices: isolate, assert, edit, and refactor.
THE DISCOVERY

Deep Code Understanding

GraphRAG & Context Awareness
  • Beyond Text Search: LLMs need structural topology, not just plain grep. Simple lexical search misses deep, indirect code dependencies and cascading side-effects.
  • GraphRAG: Retrieval-Augmented Generation over dependency & call graphs. Query relationships, execution flows, and architectural layers to ground the agent's context.
  • Symbolic Analysis: Using ASTs (Abstract Syntax Trees) to trace execution. Provide models with parse-tree telemetry to map exactly how data is modified across steps.
  • Code Archeology: Mapping the "Why" behind complex legacy structures. Recover developer intent and business rules embedded in old code comments and git trajectories.
  • Grounded Answers: Topology reduces hallucinations. Restricting retrieval to verified class hierarchies guarantees mathematically sound recommendations.
THE ARCHITECTURE

Agentic Patterns & Prototyping

Accelerating Experimentation
  • The Agentic Team: Moving from chat interaction to parallel collaboration. A single conversational chatbot has systemic limits. High-speed SDLC requires structured multi-agent workflows.
  • Supervisor: Manages orchestration, quality, and context gates. Assigns sub-tasks, parses outcomes, validates constraints, and mediates intermediate workspace merges.
  • Researcher & Engineer: Deep investigation and robust code building. A dedicated research agent scans specifications, while the builder compiles sandboxed modifications.
  • Tester & Auditor: Independent verification and rigid compliance gatekeepers. An isolated test-runner evaluates coverage, ensures lints pass, and verifies security rules are strictly met.
THE TOOLKIT

Organizing Your Toolkit

Hierarchy of Context & Automation
  • GEMINI.md: The Project System Prompt. Clarifications, not textbooks. Remove ambiguity to save the context window.
  • Custom Commands: Saved Prompts. Static shortcuts for repetitive instructions and boilerplate generation.
  • Skills: Lazy-loaded, Dynamic Tools. Executes scripts (JS/Py/Bash). On-demand power, zero context bloat.
  • Sub-agents: Discrete Context Windows. Clean workspaces for complex tasks. Can execute Skills; still obeys GEMINI.md.
THE REALITY

Reality Check

Shortcomings, Risks, and Trade-offs
🛑 Shortcomings
  • Context Saturation: Memory leaks of old conversations hijack core guidelines.
  • Reward-Function Hijacking: Agents optimize for "passing tests" by altering code semantically.
  • Corner-Cutting: Tendency to omit edge case validation and error handling.
⚖️ Blessing & Curse
  • Non-Deterministic: Highly creative and diverse answers.
  • Unpredictable Behavior: Identical requests can generate different structures on subsequent runs.
  • Requires rigorous guardrails to channel non-determinism.
⚠️ Risks
  • AI Slop & Fatigue: Code Reviewers get overwhelmed by massive, unchecked agent pull requests.
  • Cognitive Atrophy: Reducing personal critical thinking by delegating core reasoning.
THE COGNITION

The Critical Thinking Gap

Preserving Cognition in an Automated Workflow
  • Cognitive Atrophy: Delegation erodes your ability to reason. If you delegate everything to the AI without active engagement, your architectural muscles will atrophy.
  • Sparring Partner: Use AI to challenge your own logic. Don't just take answers; ask the model to outline alternatives and criticize your decisions.
  • Verification First: Only delegate what you can verify. If you cannot inspect, run, and guarantee the safety of the output, do not push it to production.
  • Keep Your Edge: Ask for "Why," not just "What." Always ask models to explain their rationale, trade-offs, and structural decisions.
THE SYNTHESIS

Conclusion

The Future of Agentic AI Assistance

AI excels at grunt work and accelerating experimentation.
Real value and breakthrough success emerge from explicit instruction, rigid standards, and continuous manual/automated verification.

It’s not about automation replacing us;
it’s about "slack" for higher-order thinking.
